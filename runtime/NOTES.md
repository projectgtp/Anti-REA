# Anti-REA v1.0 — Runtime Notes

Date: 2026-11-23. Status: **compile-verified only (JVM + smali), never device-tested.**
Scope: universal Kotlin runtime, package `com.antirea.runtime`. No Bridge
code, no app code, no secrets. Python stdlib + Kotlin stdlib only, no new
dependencies. Nothing pushed to GitHub; nothing under
`~/workspace/bridge-marketplace/` was touched.

## Files

| File | What it does |
|---|---|
| `ReaRuntime.kt` | Port of v0.1 `ReaRuntime`, blob format EXACTLY unchanged: raw = sha256(plaintext_utf8) \|\| plaintext, XOR with 32-byte key, key = part1 XOR part2, blob = base64(ciphertext). `reconstructKey`, `decrypt` (throws `IllegalStateException` on hash mismatch, never returns a wrong value), `verifyIntegrity(blob, sha256)`, `verifyText`, plus `sha256Hex` helper. No Android imports — JVM-testable. Decrypts in memory only, never logs plaintext, never writes to disk. |
| `ReaEnv.kt` | Android-only env checks, each a pure function returning `Finding(name, detected, evidence)`: `isDebuggerConnected` (`Debug`), `isEmulator` (Build fingerprint/model/hardware markers), `isRooted` (su binaries + test-keys, file-exists only, never executes `su`), `fridaMapsDetected` (`/proc/self/maps` scan for frida-agent / frida-gadget / linjector), `fridaPortsDetected` (read-only `/proc/net/tcp` + `/proc/net/tcp6` parse for LISTEN on 27042/27043), `hookLibsDetected` (xposed / substrate / edxposed / lsposed / riru in maps). `checkAll(): List<Finding>`, `suspiciousCount(): Int`. No side effects, no killing, no deleting, no network. Every file read catches exceptions and returns detected=false on error — never crashes. |
| `ReaIntegrity.kt` | Pure functions (no Android imports): `verifyDexSha256(bytes, expectedHex)`, `verifyBytesSha256`, `verifyFileSha256`, `verifyComponentBlob(blob, expectedSha256)` (delegates to `ReaRuntime.verifyIntegrity`), `verifyAllBlobs` returning `IntegrityResult(passed, failedChecks)`. Android-only section at the bottom, clearly marked: `verifyOwnApkSha256(context, expectedHex)` reads the running APK (`sourceDir`) — the only function needing `android.content.Context`. |
| `ReaTraps.kt` | Defensive traps ONLY. `Honeypot`: `registerHoneypot(id, fakeValue)` + `useHoneypot(id)` returns the fake value AND records a `TripwireEvent` via a caller-supplied callback — never sends network itself. `DelayedFailure(threshold=3)`: `recordIntegrityFailure()` + `allowSensitiveAction()` — refuses a sensitive action only after N failures; the app must call it at sensitive entry points (login, buy, settle, key generation). `ReaDecoys`: inert fake-label constants, never real keys/URLs. No bricking, no file deletion, no harm to device or analyst. |
| `ReaGuardProvider.kt` | Android `ContentProvider`. `onCreate()` runs `ReaEnv.checkAll()` + a dex/APK hash check if the `antirea/dex.sha256` asset exists, plus L101 `ReaModBlock.checkAll(context)` (modder-app signals, as `mod-tool-*` findings), stores findings in static volatile `findings` / `dexCheckPassed` / `initialized` for the app to read, and ALWAYS returns true — never crashes the app, never blocks launch. Refusal is the app's decision, not the provider's. All other provider methods are stubs (serves no data). |
| `ReaModBlock.kt` | L101 — on-device modder-app block (MT Manager etc.). Pure core (JVM-testable): `blockedPackages()` (decrypts blobs in memory; a tampered blob is skipped, never crashes), `findBlocked(installed)`, `isPackageBlocked(pkg)`. Refuse-only: never deletes, never kills another app, never harms the device. Blocklist: 13 verified package names in `ModBlockData.kt` (generated by `tools/gen_modblock_blobs.py` from `layers/MT-LIKE-BLOCKLIST.md`) — plaintext names NEVER appear in this file or in the smali. Limits: renamed clones evade the name check; Android 11+ installed-check needs host-app `<queries>` entries (CLI does not auto-inject them). |

| `ReaRepack.kt` | L103 — renamed / repacked APK defence. ## What it does NOT do (honest limits)

- **No Frida stop.** Nothing here kills Frida, a debugger, or a runtime
  memory dump. Env checks and traps are signals that something is
  suspicious; a determined attacker with Frida can read values after
  decryption and can hide from these checks. Server-side checks remain
  the real enforcement (same limit as v0.1/v0.2). L102 (2026-11-23)
  makes a memory editor's work harder to do and easier to notice
  (TracerPid, maps markers, obfuscated values) — it does NOT stop a
  determined root attacker, and it does not catch GameGuardian's
  virtual-space (no-root) mode. See `docs/GAMEGUARDIAN.md`.
- **XOR is obfuscation, not strong crypto.** An attacker who finds both
  key parts can reconstruct the key. The blob's sha256 gives tamper
  evidence, not secrecy against a skilled static analyst.
- **Env checks are signals, not proof.** Emulator/root markers can appear
  on legitimate devices (e.g. test-keys builds); a clean `checkAll()`
  (0 suspicious) does NOT prove the device is uncompromised.
- **No device test.** JVM round-trip + smali generation are verified
  below. No install, launch, or on-phone run has happened for v1.0.
- **The provider never refuses.** If the app never reads
  `ReaGuardProvider.findings`, the checks change nothing at runtime —
  integration (below) is what makes them matter.

## Integration contract for the CLI

- **Smali output dir:** `runtime/smali/` — package path
  `com/antirea/runtime/`, 19 `.smali` files: `ReaRuntime`,
  `ReaRuntime$$ExternalSyntheticLambda0/1/2`, `ReaEnv`, `ReaEnv$Finding`,
  `ReaIntegrity`, `ReaIntegrity$IntegrityResult`,
  `ReaIntegrity$$ExternalSyntheticLambda0`, `ReaTraps` (`Honeypot`,
  `DelayedFailure`, `ReaDecoys`, `TripwireEvent` + `Honeypot$$ExternalSyntheticLambda0`),
  `ReaGuardProvider`, `ReaGuardProvider$Companion`, `ReaModBlock`,
  `ReaModBlock$Finding`, `ModBlockData`. The CLI copies this
  tree into the protected APK's dex (or merges `build/runtime.jar` via
  its own d8 step — the jar is also kept at `build/runtime.jar`).
- **Decrypt entry the CLI may call** (verified present in the smali):
  `ReaRuntime.decrypt(Ljava/lang/String;Ljava/lang/String;Ljava/lang/String;)Ljava/lang/String;`
  — args: `(blobBase64, keyPart1B64, keyPart2B64)`, returns plaintext or
  throws `IllegalStateException`. Companion signatures:
  `ReaRuntime.verifyIntegrity(Ljava/lang/String;Ljava/lang/String;)Z`,
  `ReaRuntime.verifyText(Ljava/lang/String;Ljava/lang/String;)Z`,
  `ReaRuntime.reconstructKey(Ljava/lang/String;Ljava/lang/String;)[B`.
- **Provider manifest entry** (CLI writes into the protected manifest):
  ```xml
  <provider
      android:name="com.antirea.runtime.ReaGuardProvider"
      android:authorities="${applicationId}.antirea.guard"
      android:exported="false"
      android:enabled="true" />
  ```
- **Optional dex-hash asset:** CLI may emit `assets/antirea/dex.sha256`
  (one line: lowercase hex sha256 of base.apk). If absent,
  `ReaGuardProvider.dexCheckPassed` is null ("not checked"), which is
  normal — not a failure.
- **Reading findings from the app:** `ReaGuardProvider.findings`
  (`List<ReaEnv.Finding>`), `ReaGuardProvider.dexCheckPassed`
  (`Boolean?`), `ReaGuardProvider.initialized` (`Boolean`).

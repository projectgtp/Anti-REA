### Leak found and fixed during this work

The first draft of `ReaModBlock.kt` mapped known directories to
owner package names in plaintext (`"/storage/emulated/0/MT2" to
"bin.mt.plus"` …). The audit grep caught it in both the `.kt` and
the smali. Fixed: the directory path itself is the finding's
signal; the owner mapping lives only in the blocklist doc. Rebuilt
and re-grepped: 0 hits.

### Known limits (stated, not hidden)

- Renamed clones/repacks evade the package-name check (running-
  process + known-dir checks are the second/third signals).
- Android 11+: installed-check needs host-app `<queries>` entries;
  the CLI deliberately does NOT auto-inject them (they would list
  the blocked names in plaintext in the manifest).
- GameGuardian: UNVERIFIED, randomises its package name — NOT
  blocked. Recorded as a gap.
- False positive: a user with MT Manager installed for lawful use
  is blocked from the sensitive action too. Refuse-only, never
  deletes/kills/harms.

## Honest limits (whole round)

- Compile-verified + JVM/unit-verified only, never device-tested.
  L101's installed/running/dir checks have never run on a phone.
- The v1.0 manifest is an UNSIGNED SHA-256 inventory, not a
  signature. A local attacker with write access to the whole tree
  can regenerate it. A real signed manifest (public key shipped,
  private key held by the releaser) is PLANNED for the service
  phase; it cannot be done with stdlib-only Python and no secret
  in the repo, so it is not faked here.
- Python CLI source is readable; the self-check detects changes,
  it does not hide code. Obfuscation is not encryption.
- 99% is a GOAL, not a measured guarantee. No app is unbreakable;
  Frida / runtime dump still reads values after decryption.
- L101 catches official builds, not renamed clones; GameGuardian
  is not blocked; Android 11+ installed-check needs host `<queries>`.
